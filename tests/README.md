# Tests and evaluation

The tests cover per-agent tool allowlists, authorization at both handoff directions and at each tool call, context isolation, quote revalidation, idempotent mock purchases, and outbox replay. The separate evaluation harness runs normal and adversarial scenarios from `fixtures/tasks.json` and dedicated attack cases.

Step 2 adds `test_step2.py` for the bounded runtime, role allowlists, handoff and return checks, cross-tenant denial, scope checks, answer repair and sourced fallback, and the purchase stub. Step 3 adds `test_step3.py` for signed-token failures, current scopes, quote ownership and expiry, seller and budget rules, one-charge retries, an attempted concurrent double purchase, the API boundary, the integrated paid path, durable audit, outbox replay, and rollback if an audit write fails. Step 4 adds `test_step4.py` for linked buyer and researcher spans, durable denied handoffs, and delivery rollback and replay. Step 5 adds `test_step5.py` for the paid-source and free-task spend regressions, answer-grader mutations, and database-oracle mutations. The expanded harness in `src/agent_commerce_security/evaluation.py` has 19 control scenarios plus a 12-payload live attack corpus. Run `ACS_TEST_POSTGRES_DSN='dbname=agent_commerce_security_test' .venv/bin/python -m unittest discover -s tests -v`. `test_step3_postgres.py` checks atomic purchase, retry, concurrent budget use, tenant, scope, outbox deduplication, and a real worker process crash only in the dedicated `agent_commerce_security_test` database. The event sink remains local.
